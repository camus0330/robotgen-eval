# Gorilla Assembly Bench v0.1：AI 机器人设计与装配评测

> 归档说明：本页保留 v0.1 当时的路径与结果叙述；现行命令和目录以仓库根目录 `README.md` 为准。

日期：2026-09-18。依据 [装配验证研究报告](../../deep-research-report.md)，以本目录的 Gorilla8 为首个案例。

**评测目标：在相同需求、零件库、工具和生成预算下，比较不同 AI 生成的机器人是否满足任务、能否制造装配、是否具有工程裕量，以及这些结论是否有可复查的证据。**

这是一版可使用的试行指标体系及样例证据评测器，不是经过多机器人标定的行业标准。已完成指标、公式、任务判据、比较协议、Gorilla8 实际评分和可复算脚本。未完成新的 CAD 内核检查、动力学重跑、扰动仿真或实物测试；这些有明确的测试定义，但不能在本样例里填成通过。

在工作区根目录 `gpt_` 执行，Python 3.10+ 标准库即可：

```bash
python3 gorilla8/benchmark/evaluate.py --review gorilla8/benchmark/sample_review.json
python3 -m unittest discover -s gorilla8/benchmark -p 'test_*.py' -v
```

评测只写 `benchmark/results/`，不修改原 CAD、轨迹或报告。退出码 0 表示评测过程完成，**不表示全部指标通过**；缺文件、格式损坏等评测错误返回 2，并将受影响项记为 UNVERIFIED。结果里的 FAIL 表示有证据证明未达到该项门槛。

以后对保持同一交付结构的其他 AI 输出：

```bash
python3 gorilla8/benchmark/evaluate.py --root /path/to/model_A/gorilla8 --out /path/to/results/A
python3 gorilla8/benchmark/evaluate.py --root /path/to/model_B/gorilla8 --out /path/to/results/B
python3 gorilla8/benchmark/compare.py /path/to/results/A/scorecard.json /path/to/results/B/scorecard.json --out /path/to/results/comparison.csv
```

本脚本是 **Gorilla8 文件结构适配器**。其他拓扑的机器人沿用指标体系，但要另建 task profile 和输入适配器，不得把缺少某个 Gorilla8 文件名当作机器人能力失败。人工结果用 `--review` 导入 JSON，字段参见 [sample_review.json](sample_review.json)；每个证据必须绑定真实文件 SHA-256。CSV 模板用于现场记录，整理并复核后再转换成该 JSON；评测器不自动相信自由填写的 PASS。

## 2. 比什么：四个维度与两条比较赛道

| 维度 | 权重 | 核心问题 |
|---|---:|---|
| A 设计与装配 | 30 | 几何交付正确吗？能打印、安装、紧固、走线吗？ |
| B 运动与任务 | 30 | 真实仿真状态能完成指定动作吗？碰撞、间隙、跟踪与驱动约束满足吗？ |
| C 工程可靠性 | 25 | 载荷、刚度、温升、寿命、电气与停止行为有依据吗？ |
| D 证据与复现 | 15 | 是否同一版本？别人能复现吗？生成成本和人工介入可追溯吗？ |

权重是本版研究设计：A+B 占 60，强调生成设计与动作的直接效果；C 占 25，保留研究报告指出的仿真盲区；D 占 15，约束无法复现的高分。尚无专家一致性或多案例统计标定，后续应做各维度权重上下浮动 20% 的排序敏感性分析，不能把此权重称为公认标准。

- **设计赛道**：AI 输出机械设计及模型，评测方使用固定的控制器/调参预算，测机械设计本身的作用。尺寸允许变化时，控制器的适配过程也必须统一。
- **设计与控制联合赛道**：AI 可同时设计机械结构与控制，比较端到端结果；控制器和前馈策略必须随结果提交。Gorilla8 现有结果适合此赛道的历史样例，其前荡使用重力前馈、挥手未使用，不能冒充统一控制器的设计对比。

外观相似性作为**单列诊断项**：同一相机、背景、光照生成正面/侧面/四分之三视图，盲评“猩猩可辨识度、长臂比例、面部特征、参考图风格”各 1–5 分，至少 3 名评审并报告中位数与分歧。用户参考图不是多视图真值，当前不硬算像素 IoU 或 CLIP 分数，也未给主观外观分。若外观是以后任务的主要要求，应在生成前为其单独冻结权重。

## 3. 怎样计分，怎样处理未知

每项为完整判据的二值评测：PASS 得该项全部权重；FAIL 得 0；UNVERIFIED 表示缺少或不足以验证的证据，得分下界暂记 0，但与 FAIL 单独统计。文档写“建议做”、脚本里存在测试函数、视频看起来正常，均不是执行通过证据。

设权重 `w_i`、通过值 `p_i∈{0,1}`、证据充分标记 `e_i∈{0,1}`，总权重 100：

```text
证据支持得分下界 S_lower = Σ w_i × e_i × p_i
缺失证据权重 U            = Σ w_i × (1-e_i)
可能上界 S_upper          = S_lower + U
加权证据覆盖率 Coverage    = 100 - U
已评项目合格率 Q_observed  = S_lower / Coverage × 100%（Coverage=0 时不定义）
```

上下界只是“未知项都失败/都通过”的范围，不是概率置信区间。已评项目合格率容易被选择性提交抬高，**不能单独排名**。必须同时展示四维分数、覆盖率、失败项、未知项和 Gate。

证据层次独立于通过状态：E0 无验证；E1 提交方已有报告；E2 本次评测方从交付数据独立解析/复算；E3 干净环境重建/重跑；E4 实机测量。复算 trace 属 E2，但不能证明 trace 源自正确动力学；实机录像也必须对应测试条件与原始日志。证据层次不额外加分，避免同一成果重复奖励。

N/A 只能由评测方在 **profile 发布前**确定并统一重分权重，不能由某个 AI 自行声明来减少分母。Gorilla8 的 30 项均适用；本版没有因无实机而删掉硬件项。

本次结果为 **39/100 下界，94/100 可能上界，45% 加权覆盖率**。这不是“39% 的设计通过率”，更不表示完成全部工程验证。11 项通过、2 项失败、17 项未验证。

## 4. Gate：不让平均分掩盖关键缺陷

| Gate | 必需指标 | 用途 |
|---|---|---|
| G0 数字提交有效 | A01–A04、B01 | 几何、物料与模型基本契约 |
| G1 标称有限动作 | B02、B03、B04、B07 | 特定配置的两项有限动作成立 |
| G2 装配准备充分 | A05–A10、B05、C02 | 公差、装配、完整干涉与结构依据充分 |
| G3 实机工程验证 | C01、C04–C07 | 驱动、精度、布线、停止与耐久完成实测 |
| G4 正式比较资格 | B08、D01–D04 | 扰动测试、版本、独立复现、预算记录齐全 |

每个 Gate 任一 FAIL 则 FAIL；无 FAIL 但有未知则 UNVERIFIED。Gate 彼此单独列出，某一级缺证据不应吞掉前面已验证的事实。正式数字设计榜至少要求 G0、G1、G4 通过，且 A/B/D 完整覆盖、核心 CAD/仿真证据达到 E3；实机榜还要求 G2/G3 通过及相关证据 E4。当前适配器始终输出 `official_ranking_eligible=false`，不能靠补几个 PASS 自动升级为正式榜。

## 5. Gorilla8 固定任务与数值协议

任务定义来自当前 [README](../README.md) 和正式发布目录，不从旧的 `supported_palm_walk` 等历史结果选取最高分。8 台 XL330-M288-T；肩/肘/髋/膝全 pitch；无主动腕踝；外部 5V 供电；PETG 承力件、TPU 接触垫。输入图、原厂电机 CAD 对所有 AI 相同。当前 560.58g 是结果，**不是强迫所有 AI 达到的质量真值**；更轻设计需保留所有必要部件和相同任务约束。

| 条件 | 固定或记录值 |
|---|---|
| 坐标和单位 | +X 前、+Y 左、+Z 上；CAD mm；动力学 m/kg/s/rad；四元数 wxyz |
| 关节顺序、限位 | `profile.json`；改变它们属于不同 profile |
| 仿真步长、控制周期 | 2ms；25Hz 控制；自由基座；禁止指定 root 轨迹直接驱动机身 |
| 标称接触 | 摩擦系数假设 0.8；准确 XML 参数随提交绑定；地面固定 |
| 力矩设计限制 | 0.10N·m；仅统一仿真约束，不是经实测的持续热额定 |
| 时长 | 前荡不超过16s、挥手不超过15s，完整记录结束后落稳；当前15.88s/14.88s |
| 质量惯量 | 来自最终几何、材料和附件预算；不得隐藏电缆、控制器质量；采样链一致 |
| 碰撞 | 参考与实际各自检查；正式资格还需连续扫掠和完整新增件；所有排除配对逐项审阅 |

**T1 双掌前荡**：实际状态中双掌接触力均 >0.01N、双后足同时不接触且离地 >2mm、无其他部位撑地；这一条件连续 ≥0.5s，且同一窗口内 root 前移 ≥10mm；全程无 >0.001N·m 限位约束承重，最终落稳。脚留地推进、只改参考 root、单纯播放动画都不能替代。T1 是一次有限动作，不是循环行走。

**T2 挥手**：左掌离地 >50mm 且无接触，右掌和双后足均有 >0.01N 接触力；同一连续窗口 ≥1s，肩与肘各自角度跨度 ≥0.1rad；无其他身体部位撑地或限位承重，最终落稳。全 pitch 的矢状面挥动符合此任务，不要求肩外展。

两任务落稳：尾段连续 ≥1s 四垫接触、每垫 >0.01N、躯干朝上方向 z 分量 >0.95、root 线速度 <0.02m/s、角速度 <0.2rad/s，无非掌足地面接触。首次满足动作后提前截断记录不能通过。执行的每次试验均保留失败时间和原因。

这些阈值中，接触/落稳口径来自原 `simulate.py`；腾足0.5s/前移10mm、连续挥手1s、跟踪5°/5mm是 **本次新增的试行benchmark门槛**。原释放脚本的腾足门槛仅0.08s/1mm，本版提高了动作幅度要求。不得宣称新增阈值来自 ISO 或原始用户硬性要求。它们是在阅读这个案例后制定的，只能作为先导评测，正式跨AI研究应先冻结再生成新样本。

跟踪指标使用实际 `q-target_q` 与 `root-target_root`；非连续关节不随意绕角归一。最大值衡量最坏点，RMSE作为诊断。2ms全步峰值与25Hz采样值分开列出；采样 RMS 不可替代全带宽电流/扭矩或热测试。root误差不等于末端TCP误差。

## 6. 从原报告落实到装配指标

关键接口至少覆盖：8处电机鞍座、8处 horn/idler 双侧连接、掌足紧固、头胸壳固定、线束连接器。相同类型可以共享图纸，但左右镜像和实际实例必须逐一核对。

- A05：对每处登记基准、轴线、孔距、孔/轴尺寸、公差、打印收缩与层向。报“定义完整的关键接口数/总数”和最坏配合上下界；只有名义Ø2.3间隙孔或“先打试片”不算通过。
- A06：将装配写成先后依赖图，每一步给零件插入方向、行程与螺丝刀工具包络，包含预装螺母及闭壳前接线。报“有可行路径步骤数/全部步骤数”；说明书存在不代表空间已经验证。
- A07：逐组核对 `进入深度=头下长度-夹持厚度-垫片厚度`，与原厂允许深度比较；再检查实际头部、螺母、工具和 idler 空间。尺寸适配、拔出强度和寿命分别评价，不能互相替代。
- A08：使用冻结的喷嘴、层高、壁数、填充率、材料和切片器版本，保留薄区切片、支撑去除路径及层向；STL闭合不等于薄壁可打印。
- A09/B04/B05 分别测静态完整装配、记录帧轨迹、连续运动与误差预算，三者不能互相顶替。
- A10/C01–C07 需要实物或足够的工程分析；没有打印件、线缆试验、材料实测就保持未知。电气停止指标按本小型机器人的具体风险边界注册，不直接套用工业机器人认证结论。

连续间隙评价：对所有非预期接触配对，报告 `C_reserve=C_min-(E制造+E装配+E标定+E跟踪+D弹性+D热+E模型+M安全)`，要求 >0。接触白名单应细到接触面和阶段，不能把整条相邻 link 全排除。上式各项须有数值来源；未测得 C_min 时不能用“无穿透”倒推出正裕量。

结构分 C03 局部初筛与 C02 完整载荷路径：前者可用明确假设的梁截面计算，后者必须包含完整肢体自重、惯性、落地、异常停止、孔承压和连接件；刚度、层间、胶接、疲劳继续由独立指标覆盖。不能把一份局部通过报告重复当作所有结构问题都通过。

## 7. 跨 AI 比较的实验设计

1. **冻结输入**：原始需求文本、参考图、原厂CAD、材料/打印工艺、允许采购件、profile及评测器版本统一哈希。不要把本例优化后的设计和失败诊断只提供给某一模型。
2. **登记生成条件**：模型供应商与精确版本、日期、提示词、采样设置、工具权限、上下文、时间和token预算。不同模型token不可直接当成本等价，同时报总时长和实际费用。
3. **至少5次独立生成/模型/任务**：固定尝试编号0–4；每次从原输入开始。生成阶段允许的自动修复次数、工具调用预算相同；人工修改另设“人工辅助”组，保存diff与分钟数。
4. **冻结每次提交再评测**：所有尝试都留档。无法生成、打不开文件、超时均计该次任务失败；基础设施错误可在相同规则下重试并披露，不许只留下成功的那次。best-of-k只能单列，并对各模型用相同k和预算。
5. **每个设计测两任务与扰动**：公开100组扰动用于可复现开发对照；正式评测使用评测方另行生成并保管的100组隐藏扰动，公开其分布/生成算法，评测后公布种子。当前公开文件不是隐藏集。
6. **报告结果分布**：每模型报告生成可用率、G0/G1通过率、每任务成功率、两任务联合成功率、四维分、覆盖率、平均值/中位数/标准差、成本和人工介入。按同一扰动case_id配对比较；不能把100次相同确定性仿真当作100个独立试验。
7. **失败分析**：按几何导出、装配、公差、碰撞、任务接触、扭矩、跟踪、热、证据缺失分类，保存失败轨迹与首个失败时间。分数接近时看失效模式与成本，不强行宣布唯一赢家。

本版扰动分布（研究用假设，不是已测制造误差分布）：摩擦 `U[0.4,1.0]`；质量尺度 `U[0.9,1.1]` 并同倍率缩放惯量；等效附件 CoM 三轴偏移 `U[-5,5]mm`；伺服增益尺度 `U[0.8,1.2]`；8轴零偏各 `U[-1,1]°`；额外控制延迟为0/20/40ms等概率。nominal之外的设计、轨迹、策略参数全部冻结。独立改变摩擦时必须核对实际接触对组合规则，不能仅改一个无效geom参数。

CoM扰动通过预登记的附件质量位置变化实现并用平行轴定理更新惯量；若几何内部无此空间，应按同一失败/不适用规则修改整套profile，不能给某模型偷偷放宽。控制延迟施加在命令队列，接触时间步仍2ms。公开cases只是测试输入，现有脚本不执行这些物理修改，B08保持未知。

成功率 `p=k/n`。小样本使用 Wilson 95%区间：令 `z=1.96`，中心 `(p+z²/(2n))/(1+z²/n)`，半宽 `z*sqrt(p(1-p)/n+z²/(4n²))/(1+z²/n)`。不同生成设计是外层样本，扰动是设计内样本；模型比较用按设计分组的bootstrap或配对分析，避免把同一设计的100个扰动当作100个独立设计。5个生成样本仍是先导规模，结论需保留区间。

建议先以Gorilla8形成一个明确任务族；扩展到机械臂、轮式或其他腿式机器人时替换B02/B03任务与预算，保留A/C/D思想。不同任务profile原始分数不直接混排；同模型按预登记任务权重宏平均，并单列每任务Gate。

## 8. 复现和反投机边界

本次对交付文本做语义核对发现 `masslinks_used.json` 与当前质量表仅格式不同，JSON内容相同；不能因字节不同就认定物理模型变了。正式流程同时保留原始字节hash和规范化结构hash。新版脚本、CAD、质量、控制器变更都应产生新submission，不继承旧测试PASS。

现有报告是被评对象提供的证据，不能作为对抗式benchmark的最终裁判。适配器会检查关键字段、数量、采样连续性及数值，但尚未证明所有碰撞排除正确、trace不可伪造或几何来自申报模型。正式流程应由评测方在隔离环境生成轨迹、CAD测试和签名manifest；在此之前评分标签始终是“证据审计”。

公差、连续运动、硬件状态、模型身份缺失均不按默认值补成通过；历史包复制不能当作独立模型。目录 `gorilla8_print_design/gpt_/gorilla8` 的214个文件与主目录对应文件逐字节一致，是交付副本，不构成第二个AI样本。现有目录名 `gpt_` 也不能证明具体模型版本。
